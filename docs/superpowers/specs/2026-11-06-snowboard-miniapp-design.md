# 单板滑雪学习小程序：第一版设计

日期：2026-11-06

状态：用户已于 2026-11-06 回复“按文档继续”，本文通过审阅，进入实施计划。

## 1. 目标与范围

帮助单板学习者按照课程顺序学习、练习，上传自己的练习视频并进行自评打卡，持续记录进步。

已确认的选择：微信小程序；学习路线型产品；视频记录打卡；当前没有教学视频或动图，先用文字课程和明确的媒体占位完成第一版；后续可以扩展 AI 滑行视频分析。

第一版交付学习路线、课程详情、视频练习打卡、个人练习记录四项能力。入门阶段提供完整课程页面和学习流程。进阶阶段仅显示“课程筹备中”，没有虚构课程、考核或可进入的空页面。

第一版不包含 AI 评分、教练审核、社区、付费课程、排行榜、课程管理后台或自动判断动作是否正确。课程完成统一称为“自评完成”。

成功标准：用户能从入门第一课开始，阅读教学、保存一次未达标练习、上传视频完成自评、解锁下一必修课，并在重新进入小程序后看到相同进度与练习记录。

## 2. 页面与导航

底部两个入口：“学习”“我的”。课程详情、打卡与记录详情从对应入口进入，不额外增加底部入口。

### 2.1 学习首页

- 顶部显示当前阶段、必修完成数量和“继续学习”按钮。
- “继续学习”进入最早一个尚未完成且已解锁的必修课程；必修全部完成后进入本阶段回顾。
- 路线按顺序展示课程名称、必修/选修标识和状态：待解锁、可学习、自评完成。
- 待解锁课程可查看简介、学习目标和前置要求，不能进入完整教学或提交打卡。
- 已完成课程始终可重新阅读和练习。
- 选修课单独标识，不影响必修进度分母或阶段完成。
- 阶段完成显示“入门阶段已自评完成”，提供复习入口；进阶显示筹备状态。

### 2.2 课程详情

顺序为：课程名称与学习目标 → 教学媒体 → 动作拆解 → 关键要点 → 常见错误 → 考核清单 → 练习入口。

- 教学媒体缺失时显示静态占位和“教学视频待补充”，不显示可播放按钮、假进度或失败播放器。
- 后续同一媒体区域可支持视频或动图；无媒体时仍能阅读文字。
- 考核项使用稳定 ID，不能只依赖显示顺序；每次练习重新勾选，不能自动沿用上次结果。
- 已完成课程底部显示“再练一次”；未完成且已解锁课程显示“开始练习”。
- 内容草稿显著显示“课程草稿，待教练校对”，开发预览不将草稿包装为已验证的教学。

### 2.3 练习与打卡

- 显示对应课程的考核清单、单个练习视频选择区、可选心得。
- 产品默认每次记录一个视频，最长 3 分钟、最大 100 MB，心得最长 500 字。上述为本产品限制，不代表平台上限；接入时使用兼容的媒体接口并在真机验证。
- 支持从相册选择或拍摄；选择后可本地预览、移除或替换。
- 接口核对补充：拍摄入口保守设置为最多 60 秒；相册导入仍执行最多 3 分钟的产品限制。依据微信官方类型定义中的拍摄时长说明，真机验收时分别验证这两个入口。
- 提供两个明确操作：“保存练习”和“完成打卡”。
- “保存练习”允许考核项未全部勾选，但仍需上传视频；记录结果为“练习中”，不解锁课程。
- “完成打卡”要求全部考核项勾选、视频已上传并通过服务端校验、课程已解锁；提交成功后记录为“自评完成”。
- 显示上传进度，上传和提交期间避免重复触发；用户主动取消时保留文字及勾选状态。
- 临时视频路径只用于本次本地预览，不作为云端记录。重新打开页面若临时文件失效，保留文字草稿并提示重新选择视频。
- 无视频时只能保留本机草稿，不生成正式练习记录或完成进度。

### 2.4 我的与记录详情

- “我的”显示必修完成数、已提交的练习次数和按时间倒序的个人记录。
- 可按课程筛选，每条显示课程、提交时间、练习中/自评完成、视频缩略图或统一占位。
- 详情显示视频、该次考核结果、心得及课程内容版本。
- 用户可删除自己的记录及关联视频，删除前明确提示；已获得的课程完成状态保留，删除记录不重新锁课。
- 删除后课程完成凭证只保留课程、版本和完成时间，清除对应记录引用，不保留视频或心得。
- 空记录状态引导去学习；网络失败提供重试，不能伪装成“没有记录”。

装备、站姿等课程同样遵循视频打卡规则：用户可以上传该课相关练习或讲解记录，不要求录制滑行。

## 4. 学习进度规则

- 打开页面或看完教学媒体不等于完成课程。
- 课程只有一个持久完成状态，但可拥有多次练习记录。
- 每个用户、每门课程最多一条首次完成凭证；重复完成增加练习记录，不重复增加完成数。
- 解锁由课程前置条件和服务端完成凭证计算，不能由客户端提交“已解锁”布尔值控制。
- 必修完成数分母固定取当前已开放阶段的必修目录，选修不计入。
- 完成全部 10 门必修即完成入门阶段；不存在基于此自评结果的技能认证或 AI 判定。
- 内容更新采用版本号；既有记录保留当时的考核项快照，既有完成进度不因文案更新失效。
- 不支持直接跳过必修课、导入既有水平或付费解锁。

## 5. 技术架构

选用原生微信小程序（WXML、WXSS、TypeScript）和微信云开发。选择依据是当前只交付微信小程序，需要账号关联、视频上传、持久化记录；不引入跨端框架、自建登录系统或自建服务器。

模块边界：

1. 课程数据：仓库内维护版本化的结构化内容，生成前端展示资源和服务端考核配置，避免两端各自维护规则。
2. 进度规则：独立纯函数处理前置课程、必修计数及下一课，便于单元测试。
3. 小程序页面：负责展示、交互、媒体选择、上传进度和草稿保存。
4. 客户端数据服务：统一封装云函数、上传与错误映射，页面不直接读写业务数据库。
5. 云函数：识别当前用户，管理上传会话、校验打卡、读取进度与个人记录、执行删除。
6. 云数据库与私有云存储：保存练习、完成凭证及视频；不将视频二进制放进数据库。

课程可在未连接云环境时阅读。没有有效云配置时，云操作显示明确的不可用状态；开发测试可注入模拟数据服务，但正式模式不能静默返回假上传成功或本地模拟完成。

### 数据实体

| 实体 | 关键字段 | 约束 |
|---|---|---|
| Stage | id、title、order、availability | 入门开放，后续筹备 |
| Lesson | id、stageId、order、optional、prerequisiteIds、version、reviewStatus、goal、steps、keyPoints、commonMistakes、criteria、media | criteria 包含稳定 id 和文字；media 可为空 |
| UploadSession | id、ownerId、lessonId、cloudPath、fileId、state、createdAt、expiresAt | 路径由服务端分配，归属不可由客户端指定；24 小时有效 |
| PracticeRecord | id、ownerId、lessonId、lessonVersion、criteriaSnapshot、checkedIds、videoFileId、note、result、createdAt | result 为 practicing/selfCompleted；时间由服务端生成 |
| LessonCompletion | ownerId、lessonId、lessonVersion、firstCompletedAt、sourceRecordId | 用户与课程唯一；由服务端创建 |

不要求用户提供手机号、头像、昵称或位置。服务端身份用于归属校验，不作为前端可编辑字段。

## 6. 上传、提交与读取

1. 页面读取课程和该用户进度，允许解锁的课程进入练习。
2. 用户选择一个视频，在客户端检查时长、大小与文件类型，预览并填写考核、心得。
3. 服务端创建绑定用户与课程的上传会话，并返回唯一上传路径。
4. 客户端将视频上传到该路径，保留 fileId 和会话 ID；失败可重新上传，不创建练习记录。
5. 提交时服务端重新检查身份、课程版本、前置条件、考核项、心得长度、会话归属及有效期、文件存在性和文件归属。不能仅凭客户端声称上传成功放行。
6. 文件大小及可取得的媒体元信息在服务端复核。若接口不能提供可信时长，必须明确时长仅为客户端产品限制，不将它当作服务端已验证的安全条件。文件类型需结合存储元信息与文件签名检查。
7. 保存练习只创建记录；完成打卡在同一数据库事务内创建记录、首次完成凭证并消费上传会话。
8. 同一个上传会话作为提交幂等键。重试返回原记录；已消费会话不得重复生成记录或完成凭证。
9. 客户端收到提交成功后刷新进度；响应丢失时用同一幂等键重试，不能提前展示解锁。
10. 读取记录或获取视频播放信息时再次检查所有者。临时播放地址只按需获取，不持久化或用于分享；失败时允许刷新地址。

### 文件与数据权限

- 练习视频默认仅创建者可读写；课程教学媒体将来单独管理，不与用户私有视频混用公开权限。
- 业务数据库禁止客户端直接读写，由云函数统一执行所有者校验。
- 云函数具有管理侧权限，因此每条读取、提交、删除及播放请求均需要独立校验身份和资源归属，不能只依赖客户端存储规则。
- 上传只能落在当前用户的允许路径，限制覆盖他人文件；路径前缀不是唯一的归属证明。
- 日志不记录视频临时地址、完整心得或访问凭据。
- 删除记录先标记删除中并隐藏，幂等删除视频后清理记录及完成凭证的引用。失败允许重试并由清理任务补偿，不能宣称文件已删除。
- 未关联成功记录的过期上传文件，在会话超过 24 小时后由清理任务删除；清理与提交通过会话状态互斥，避免删掉正在提交的文件。

## 7. 异常与体验

| 情况 | 预期行为 |
|---|---|
| 拒绝相册或摄像头访问 | 解释需要访问的用途，提供重选或返回，保留草稿 |
| 视频超过产品限制 | 在上传前说明大小或时长限制，允许重新选择 |
| 上传中断 | 显示失败和重试，不解锁下一课 |
| 云端提交失败或超时 | 保留会话与表单，使用同一幂等键重试 |
| 考核未全部勾选 | 可保存练习，不能完成打卡 |
| 课程版本已更新 | 提示重新载入考核项并再次确认，保留视频和心得 |
| 登录身份暂不可用 | 保留本机草稿，提示重试，不伪造云端记录 |
| 视频不存在或播放失败 | 显示不可播放和重试，保留其他记录信息 |
| 记录删除失败 | 提示删除处理中或可重试，云端继续补偿 |
| 云端进度读取失败 | 保留可阅读课程，不把未知进度显示为零 |

页面采用中文，保证户外使用时关键文字和按钮易识别；完成、未完成、上传失败等状态同时使用文字，不仅依赖颜色。最终视觉样式在页面实现中统一处理，不将未选择的主题设计写成已确认需求。

## 8. 验证与交付标准

### 自动化验证

- 前置依赖：首课开放、完成后解锁、选修不阻塞、未开放阶段不能打卡。
- 进度计算：必修 10 课分母、重复完成不加分、删除记录不回退、全部必修完成后的下一步行为。
- 提交校验：缺视频、缺考核项、伪造用户、非本人文件、过期会话、错误版本及未解锁课程均不能完成打卡。
- 幂等和事务：重复请求、并发请求、响应丢失及写入中途失败不生成重复或半完成状态。
- 权限：用户 A 无法读取、播放或删除用户 B 的练习视频和记录，直接存储访问同样验证。
- 清理：不删除已关联记录的文件；删除重试和过期会话清理可以重复执行。

### 微信开发者工具与真机验收

- 两个底部入口、11 课目录、媒体占位、锁定预览、草稿提示和返回行为符合设计。
- 至少完成一次真实视频选择、上传、未达标保存、达标提交、下一课解锁、退出后恢复、回看和删除。
- 验证相册拒绝、弱网、上传取消、重复点击及播放地址失效。
- 使用两个测试账号核对视频和记录隔离。
- 目标微信环境实际验证产品设定的 3 分钟及 100 MB 边界；若真实能力限制更低，明确调整产品限制和文案，不伪造通过。

自动化测试通过不等同于真机验证完成。真实上传验收需要用户拥有的小程序 AppID、云环境和开发者工具；项目中只提供配置示例，不写入密钥，也不虚构这些资源已配置。创建付费环境或公开发布不属于本次设计确认的自动执行范围。

### 内容与发布验收

课程目录和所有页面完整；缺少教学视频是已接受的首版状态。技术测试通过后，动作文字及考核草稿仍需内容校对，公开发布时不得仍使用未审阅的课程草稿。视频功能按真实云环境验收结果报告，不能把模拟流程称为已完成生产上传。

## 9. 后续扩展边界

- 教学视频或动图：填充课程 media 字段并更新内容版本，不改变打卡结构。
- 进阶课程：新增阶段及版本化课程，明确前置条件后开放；不预先编造完整精通课程。
- AI 分析：未来新增与 PracticeRecord 关联的分析任务及结果，单独征得视频处理授权；当前不上传给 AI 服务、不展示虚构评分，也不预建空的分析后台。
- 教练点评：未来作为独立结果记录，不覆盖已有自评历史。
